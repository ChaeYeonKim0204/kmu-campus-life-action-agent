## 1. 🔴 가장 큰 전환 — "LLM 로드맵 플래너"를 결정론으로

**기획 (direction §2·§5):**
> 컴퓨터=사실 → **LLM=로드맵 계획**(선수·개설학기·부하·관심 *판단*) → 컴퓨터=검증 → 실패 시 1회 repair → 그래도 실패면 솔직한 실패.
> "이래서 계산기도 ChatGPT도 아닌 자리."

**실제:** 로드맵 배치 자체를 **결정론 greedy 통합 플래너**가 한다 (`planner.py: build_unified_candidates → plan_greedy`).
- 남은 의무(필수·융합 그룹 quota·전공 갭·교양 슬롯·일반선택 residual)를 **단일 후보 풀**로 정규화 →
- 우선순위·선수 위상·Ⅰ/Ⅱ 번호 시퀀스·개설학기·학점 상한을 지키며 greedy 배치 →
- 결정론 검증(미배치/gap_not_closed → blocked) → 초과학기 시나리오 환산.
- LLM 경로(`plan_roadmap`/`validate_roadmap`)는 **코드만 보존, 호출 안 함**.

**왜 바뀌었나:**
1. **루브릭 직격** — 교수가 구두 강조한 "출력 무작위성 통제·매번 일관된 결과". LLM 계획은 같은 입력에도 흔들리고, repair 루프는 데모 시간·신뢰도 리스크.
2. 초기 LLM 시안의 품질이 낮았음 ("시나리오가 너무 거지같음") → codex와 설계 협의(`reviews/codex_llm_placement.md`) 결과 **"배치는 제약충족 문제라 결정론이 정답, LLM은 도구 선택(ReAct 컨트롤러)·RAG Q&A에 배치"** 권고 채택.
3. 결정론이 되면서 검증·회귀가 가능해짐 → 수렴 루프에서 "동일 입력 3회 해시 동일"을 보장.

**남는 것:** direction의 "계산은 컴퓨터, 판단은 LLM" 원칙 자체는 폐기가 아니라 **LLM의 자리를 이동** — 차기 작업인 RAG Q&A(요람 근거 인용 답변)와 bounded ReAct 컨트롤러(어떤 도구를 쓸지 선택)로 간다. CLAUDE.md의 ReAct 가드레일("LLM은 next_tool만 고른다") 방향과 합류.

## 2. 🔴 범위 확장 — "한 학과 깨끗한 데모"에서 "학번별 요람 + 다전공 풀 모델"로

**기획:** AI빅데이터융합경영 한 학과, 1~2개 입학연도, 부전공은 예시 한 줄. 연계융합 composition_rules는 스펙에서 **컷** 예정이었음.

**실제로 커진 이유 — 실데이터가 이끌었다:** 검증에 쓴 실제 수강내역(9개 .xls)이 **미래모빌리티 2023학번 + 모빌리티데이터 다전공** 학생이라, happy path를 매끄럽게 만들려면 다음이 전부 필요해졌다:

| 추가된 것 | 내용 | 근거 데이터 |
|---|---|---|
| 학번별 요람 적용 | "20230000이면 2023 요람" — `requirements_by_year.json`(영역최저: 미래모빌리티 2023 기초8·핵심17(소통5)·전공62·총136), `required_names_by_year.json`(필수과목+개설학기+양방향 alias), nearest-prior 연도 폴백 | 학사규정·연도별 요람 |
| 연계·융합전공 모델 | 다전공(요건36·캡12·그룹최저12) / 부전공(18·6·6), **중복인정은 캡 한도 내만 양쪽 동시 인정**, 초과 겹침은 과목별 **3-way 선택**(중복인정/제1전공/융합 — 프론트 SEL + 백엔드 기본배정 동일 산식), **전공필수는 융합 전용 이동 금지**, 그룹별 최저=이수 커버리지 | 학사규정 제77조 + 사용자(도메인) 확정 규칙 |
| 학기당 학점 상한 | 제32조: 졸업학점 130→18 / 136→19 / 120→17, 계절 6, **직전학기 3.75↑ → 다음 한 학기만 +3** (기획의 "과목 수" 모델은 사용자 결정으로 폐기 — 잔재 필드도 제거) | 학사규정 제32조 |
| 교과목 매칭 강화 | 교과목코드 7자리 우선(기획대로) + 5자리 prefix 충돌 시 7자리+이름 폴백, 카탈로그 밖 코드만 이름 매칭, 로마숫자/공백 정규화 | 2025 교육과정 코드현황 |

→ direction §1의 차별점 "**정합성**(내 데이터·내 요람)"은 그대로인데, "내 요람"의 정의가 *"학과 요람"*에서 *"내 학번의 요람 + 내 다전공 규정"*으로 깊어진 것.

## 3. 🟡 "솔직한 실패"에서 "초과학기 컨설팅"으로

**기획 (§2):** 검증 실패 → 1회 repair → 또 실패면 *"이렇게는 안 됨, 이유는 X"* 표시로 끝.

**실제:** 실패를 끝이 아니라 **컨설팅의 시작**으로 바꿨다 (사용자 피드백: "졸업이 불가능하면 초과학기 예상 시나리오를 보여주는 게 더 나음.. 지금은 너무 멍청함").
- blocked여도 **배치 가능한 부분은 전부 배치해 보여주고**(은닉 금지 — 수렴루프 R2 수정),
- 미배치 학점을 학기당 상한으로 환산해 **"초과학기 N학기 → 예상 졸업 20XX-X"** 산출(`OverflowScenario`),
- N=1이면 **잔여+1 재배치를 실제로 돌려 경로를 검증**(개설학기 deadlock이면 "추산·경로 미확정"으로 표시) — 검증 통과 시에만 리스크 D→C 완화.

리스크도 기획의 3단(안전/주의/위험)에서 **A/B/C/D 4단 + 결정론 트리거**(총학점·전공필수·영역·잔여수용량·핵심교양·융합·평점)로 — "졸업불가 가능성(D)" 배지와 "1학기 더 다니면 졸업" 카드가 모순 병치되지 않도록 완화·문구 4분기 체계까지 정리(수렴루프 R4~R6).

## 5. ➕ 기획에 없던 신규 산출물

1. **워크플로우 그래프 시각화** (`WorkflowGraph.jsx`, `#workflow` 별도 페이지) — direction엔 없고 루브릭("Dify처럼 노드 분기를 눈으로")에서 옴. 백엔드가 `node_trace`(9노드: 요람 로딩→…→리스크 산정→리포트, branch_taken 포함)를 방출하고 프론트가 점등 리플레이.
2. **데모 학생 패키지** (`data/graduation/v2/demo_students/` + `scripts/make_demo_students.py`) — ai_bigdata+데이터사이언스 다전공 합성 학생 4명(.xls 20개): 겹침>캡 3-way(S1)·그룹 공백(S2)·초과학기 D(S3)·계절+성적우수(S4). direction §8의 "깨끗한 샘플" 요구를 시나리오별 검증 자산으로 확장.
3. **검증 캠페인 기록** (`docs/reviews/review_round*.md`) — 적대리뷰 5라운드(+codex 동수) 후 수렴 루프 7라운드: 라운드당 서브에이전트 3+codex 3, CRITICAL 0건(R7 전원)까지. 잡은 실결함 ≈ 16건(슬롯 시퀀스 오인 대량미배치, credits 오염 OOM, 표면 모순 등).

## 7. 교훈 한 줄씩

- **결정론이 이긴다 (이 루브릭에선)**: "agentic해 보이는 것"보다 "매번 같은 정답"이 채점 포인트였고, LLM은 빼는 게 아니라 *옮기는* 것이었다.
- **실데이터가 스펙을 다시 쓴다**: 진짜 성적표 한 부가 학번별 요람·다전공 모델 전체를 끌고 들어왔다 — 종이 기획에서 "한 줄"이던 부전공이 실제론 최대 모듈이 됐다.
- **실패 화면도 제품이다**: "안 됨"으로 끝내는 대신 "몇 학기 더"를 계산해 주는 것이 컨설팅 보고서라는 정체성에 맞았다.
- **적대 검증은 코드만큼 산출물이다**: 수렴 루프가 잡은 16건 중 다수는 단위 테스트로는 안 잡히는 *표면 간 모순*이었다.
