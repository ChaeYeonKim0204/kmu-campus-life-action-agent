# 교수 구두 피드백 원문 메모 (발표 준비 기준점)

> 출처: 수업 중 구두 피드백(팀 기록). 발표·Q&A 준비는 이 문서를 기준으로 검증할 것.

## 1차 피드백

- **상용 LLM이랑 어떤 차별점이 있는지?**
- **너무 많은 서비스를 담고 있음!** 학교생활 챗봇 만드는 거 (서비스 과다 비판)
- 그 안에 작동되는 **에이전트 특징**이 있어야...
- 졸업증명서·요람·규정집·성적증명서를 바탕으로 해서..
- **ReAct를 풀어야 함**
- 학교생활하면서 하는 일들 중에서...

## 2차 피드백

- **이 에이전트를 써야만 하는 이유? 필요성이 강조**가 되어야 함
- 개인 DB를 구축해서 식단을 추천해준다던가 (예시)
- **RAG 기반 졸업사정 + workflow가 독특하게 나오는 거 다른 거 하나** (← 두 번째 워크플로우 기대)
- 학교생활 전반적인 도움을 주는 뭔가면 괜찮은데

## 3차 피드백

- **텍스트만 뿌려줄 게 아니라 졸업사정 컨설팅 보고서 형태로**

## 피드백 ↔ 현재 구현 대응표 (2026-06-04 기준)

| 교수 피드백 | 대응 상태 |
|---|---|
| 서비스 과다 → 줄여라 | ✅ 티어1(/ask 챗봇) 제거, 졸업센터 단일 축 |
| 개인 DB + 공식 자료 grounding | ✅ 수강내역 .xls × 학번별 요람 × 학사규정 |
| 컨설팅 보고서 형태 | ✅ 섹션형 보고서(판정 배지·게이지·로드맵·해설·citation 토글) |
| 차별점·필요성 강조 | ✅ demo_script "vs ChatGPT" 비트(중복인정 캡·학번별 요람·결정론) |
| **ReAct를 풀어야 함** | ⚠️ **발표 프레이밍 필요** — 상담 Agent를 "bounded(1-step) Tool Calling, ReAct의 안전한 특수형"으로 명시하고, 왜 멀티스텝 ReAct를 의도적으로 제한했는지(출력 일관성 루브릭)를 정면으로 설명해야 함. 회피하면 감점 위험 |
| **워크플로우 다른 거 하나** | ⚠️ **발표 프레이밍 필요** — 졸업사정(RAG·판정형) vs **졸업 시나리오 상담(what-if 시뮬레이션형)** 을 "서로 다른 워크플로우 archetype 2개"로 명시 제시(상담은 second_topic 후보였던 시뮬형의 구현). +팀원의 커리어 에이전트(HITL형)가 있으면 3개 |
