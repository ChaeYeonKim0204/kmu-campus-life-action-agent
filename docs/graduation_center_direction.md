## 1. 큰 틀 — "내 학번·내 전공에 정확히 맞춘 졸업사정 컨설턴트"

ChatGPT는 *일반론*("보통 전공 X학점 필요")만 말한다. 우리는 **당신의 입학연도 요람 × 당신의 전공 구성 × 검증된 당신의 성적표**로 정확히 진단한다. → **정합성(데이터 정확성) 자체가 차별점.**

핵심 통찰: 졸업센터의 가치는 "화려한 agentic"이 아니라 **"내 데이터·내 요람을 정확히 맞추는 정합성"**. 그리고 그 정합성을 확보하면, 그동안 과하게 "확인 필요"로 떠넘기던 답변을 **자신 있게 단정**할 근거가 생긴다.

## 2. 차별화 근거

### vs ChatGPT (왜 상용 LLM으로 안 되나)
ChatGPT는 ① 입학연도별 요람 차이를 모르고 ② 내 성적표를 정확히 못 읽고 교정도 못 하며 ③ 요람에 없는 과목을 환각으로 채운다. 우리는 셋 다 grounded로 막는다. 특히 **OCR↔요람 대조 자기교정 + 모르는 건(타과 과목) 사용자에게 질의**하는 동작이 수동적 Q&A와 다른 "agentic"의 정직한 정의다. ("ReAct"라는 알고리즘 라벨에 매이지 않는다 — 교수 진의는 *상용이 못 하는 차별화된 agentic*.)

### vs 커리어 에이전트 (두 번째 주제) — workflow가 달라야 한다
교수가 두 주제의 workflow가 다르길 원함. 둘은 실제로 다르다:

| | 커리어 에이전트 | 졸업센터 |
|---|---|---|
| 데이터 | 외부 공지(비정형) | 개인 성적표+요람(정형) |
| 핵심 난제 | 일정 충돌·행동 승인 | OCR 정확성·요람 버전·전공 구성 |
| 사용자 개입(HITL) | **행동 승인**(실행 전) | **데이터 검증**(분석 전) |
| 끝점 | 외부 액션 실행(캘린더/노션) | 정밀 진단·로드맵 산출 |
| 성격 | 행동형(executor) | 컨설팅·분석형(analyst) |

둘 다 "사용자 확인" 단계가 있어도 **목적이 정반대**(행동 게이트 vs 데이터 게이트)라 대비가 또렷하다.

## 3. 워크플로우 [1]~[7]

```mermaid
flowchart TD
    C1["[1] 컨텍스트 선입력<br/>학번(→입학연도)·본전공·다/부전공·연계융합전공"] --> C2["[2] 요람 로딩<br/>그 연도·전공 요람 부분만 (데모: AI빅데이터융합경영학과)"]
    C2 --> C3["[3] 성적표 업로드 → GPT OCR 파싱"]
    C3 --> C4{"[4] 요람 기반 자동 교정"}
    C4 -->|요람에 있는 과목| C4a["표준 과목명·이수구분으로 OCR 오류 교정"]
    C4 -->|요람에 없는 과목<br/>(타과 수강 등)| C4b["임의 변경 금지 · '확인 필요' 플래그"]
    C4a --> C5["[5] 사용자 검증(HITL)<br/>파싱·교정 결과 표로 보여주고 편집 → 데이터 확정"]
    C4b --> C5
    C5 --> C6["[6] 졸업사정<br/>영역별 갭 계산 → 부족 시 대체경로 탐색 → 리스크 등급화"]
    C6 --> C7["[7] 시각 졸업 로드맵 대시보드 + 컨설팅 보고서(근거 토글)"]
```

**[6] 졸업사정 내부 — 직선이 아니라 분기·수렴:** 갭을 발견하면 메울 수 있는 여러 경로를 탐색·비교해 하나로 수렴한다(커리어의 선형 파이프라인과 대비되는 모양).
```
영역별 갭 계산 → (부족 발견)
   ├─ 대체과목 탐색      ┐
   ├─ 마이크로디그리      │ 각 경로 평가·비교
   ├─ 조기졸업 가능성     │ (부족하면 추가 탐색)
   └─ 계절학기/추가이수   ┘
        ↓ 수렴
   리스크 등급화 → 학기별 로드맵
```

## 4. task 구성 — audit 플래그십 + 나머지는 도구

기존 8개 task(audit·조기졸업·커스텀전공·성적포기·대체과목·마이크로디그리·졸업후체크리스트·직무역량번역)를 **별도 단발 기능이 아니라**:
- **audit(졸업사정)** = 메인 플래그십. [1]~[7] 전체 플로우로 깊게 구현.
- **나머지** = audit의 [6]단계에서 호출되는 **도구(대체경로 탐색기)** 로 재활용. 별도 엔드포인트로 노출하기보다 졸업사정 안에서 필요 시 동작.

→ "8개 곁다리"가 "하나의 졸업사정 컨설팅"으로 통합됨.

## 5. 보고서 / 대시보드 (Q3=2 시각 대시보드형)

산출물은 텍스트 나열이 아닌 **시각 졸업 로드맵 대시보드** + 컨설팅 보고서:
- 영역별 이수 현황(학점 게이지·부족분 차트)
- 졸업 리스크 등급
- 학기별 액션 로드맵(타임라인)
- 컨설팅 보고서 섹션(현황진단 / 부족요건 / 대체경로 시나리오 / 학기별 액션플랜)
- **근거(citation)는 기본 접힘 + "근거 보기" 토글** — 내부적으로는 G1/G2 마커 생성·검증 유지

> 역할 분담이 모델/프론트가 아니라 **졸업센터 vs 새 주제**로 바뀌어, 졸업센터 담당이 분석+대시보드 **풀스택**을 가짐 → 시각 대시보드가 한 사람 범위 안에 들어옴.

## 6. 기존 코드에서 걷어낼 옛 규율

현재 `graduation_center` 코드는 옛 CLAUDE.md의 강한 규율(성적표=독성 PII → 마스킹·비반환, 과잉 헷지)을 그대로 구현 중이고, 이는 새 방향과 정면 충돌한다.

### (A) 과잉 마스킹 — 내 데이터를 가려서 검증·표시를 막음
| 위치 | 옛 규율 | 변경 |
|---|---|---|
| `parser.py` `masked_name`/`masked_student_id` | 이름·학번 마스킹 반환 | [5] 검증 위해 **실제 값 보존·표시**(내 데이터) |
| `service.py` `SENSITIVE_PATTERNS`/`_sanitize_sensitive_output` | GPA·성적·이메일·학번 마스킹 | **학번 뒷자리 정도만** 또는 거의 해제(보고서·대시보드에 내 성적·GPA 표시) |
| `status().privacy` `returns_gpa_value:False` 등 | "GPA·과목성적 절대 반환 안 함" 계약 | 내 데이터 표시와 모순 → 계약 갱신 |
| `_input_safety_flags` blocked 경로 | 민감정보 감지 시 차단 | 성적증명서엔 주민번호 없어 대부분 무의미 → 최소화 |

### (B) 과잉 헷지 — 뭐만 하면 "몰라요/확인 필요"
| 위치 | 옛 규율 | 변경 |
|---|---|---|
| `_analysis_prompt` 규칙 | "판단 못 하면 '확인 필요'로", "확정 말고 안내" | **근거 있으면 단정** 원칙으로 교체 |
| `_build_answer` | 항상 `[학과·교무팀 확인 질문]` + `[최종 확인]` 꼬리표 | 반사적 면피 제거 → **정말 필요한 항목에만** |

**답변 원칙(신규):** "근거 있으면 단정, 진짜 모를 때만 모른다."
- 계산 확정(학점 갭·이수구분 충족) → 단정
- 요람 명시 규정 → 근거 달고 단정
- 진짜 학과 재량·요람 밖(타과 인정·개별 승인) → *그때만* "확인 필요"

**과잉 헷지의 근본 원인 = 데이터를 못 믿어서**였고, 새 방향([1]~[5]의 정합성 확보)이 그걸 해결하므로 자신 있게 답할 근거가 생긴다.

### 유지할 최소 경계 (프라이버시 0은 아님)
- 외부 유출 금지(타인에게 전송·영속 저장 안 함)
- 데모·공유는 **본인 또는 더미 성적증명서**로(공개 화면 노출 대비)

## 7. 프로토타입 범위

- **학과**: AI빅데이터융합경영학과 **한정**으로 요람을 이쁘게 잘라 인덱싱(전 학과 X).
- **요람 연도**: 1~2개 입학연도만 확보, 데모 학생은 그 연도로(전 연도 X). "학번별 요람" 로직은 그 안에서 동작하게 설계.
- **깊이 > 넓이**: audit 하나를 매끄럽게 끝까지 (좁되 정확하게).

## 8. 더 디벨롭할 거리 (다음 논의 시드)

- **[2] 요람 로딩**: 입학연도·전공 구성 → 요람 범위 매핑을 어떻게 구조화할지(메타데이터/필터링). 연도별 요람 데이터 확보 방법.
- **[4] 교정 경계 알고리즘**: 요람 과목 카탈로그와 OCR 결과를 매칭하는 방식(정확 일치/유사도), "있음/없음" 판정 기준, 교정 vs 보존 규칙의 구현.
- **[5] 검증 UI ↔ 백엔드 데이터 흐름**: 편집 결과를 어떤 형태로 받아 [6]에 넘길지.
- **[6] 리스크 등급화 기준**: 등급 정의(예: 안전/주의/위험)와 산정 로직(결정론).
- **[6] 대체경로 탐색**: audit 안에서 대체과목·마이크로디그리·조기졸업 도구를 *언제* 호출할지(조건/순서).
- **[7] 대시보드 시각 요소** 구체화.
- **node trace 스키마**: 각 노드 실행을 구조화 trace로 방출(Dify식 시각화 토대) — 커리어 에이전트와 공유할지.
